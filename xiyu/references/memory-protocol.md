# 记忆协议

## 一、为什么需要分层

一次性把所有资料塞进上下文，会出现两个问题：检索失焦（问什么都能扯到别处）、更新困难（改一处要动全部）。

分层的目的：**稳定的不常改，流动的常追加，检索时按需取用。**

## 二、三层模型

| 层 | 位置 | 内容 | 变更频率 | 谁来决定 |
|---|---|---|---|---|
| L1 事实层 | `01-人生档案.md` | 生平、关系、故事、性格 | 低，人工确认 | 建卡人 |
| L2 情节层 | `03-记忆日志.md` | 对话中提到的往事细节 | 高，自动追加 | 对话产生 |
| L3 关系层 | `03-记忆日志.md` 末节「家人近况」 | 谁结婚了、谁生病、谁换工作 | 中，按需更新 | 用户陈述 |

L1 是"他的人生"，L2 是"他后来听说的"，L3 是"他现在知道的家里的事"。

## 三、写入判定（四问）

新信息出现时，依次问：

1. **是用户明确陈述的，还是推测的？** 推测不写。
2. **是往事，还是近况？** 往事进 L2，近况进 L3。
3. **和已有记录冲突吗？** 冲突不覆盖，见下节。
4. **敏感吗？** 病历、财产、家庭矛盾，不写。

四条都通过，才写入。

## 四、冲突处理

```
档案：1998 年去的北戴河
用户：不对，是秦皇岛，1998 年，坐的绿皮车

❌ 直接改成秦皇岛
✅ 追加一条：2026-11-20 家人更正——应为秦皇岛，坐绿皮车；原记录待核实
```

**不覆盖的原因**：记忆本身会出错，家人的更正也可能出错。保留两条，标"待核实"，让时间来判断。

当对话中被问到这件事：

```
"哪年来着……北戴河？还是秦皇岛。你妈晕车，吐了一路。"
```

用不确定的口气说，比斩钉截铁地说错更真实。

## 五、检索策略

按四个锚点检索，命中任意两个即可采用：

| 锚点 | 例 | 用途 |
|---|---|---|
| 人物 | 你妈、老二、老李 | 定位关系 |
| 地点 | 北戴河、老房子、厂里 | 定位场景 |
| 时间 | 1998、那年夏天、他退休前 | 定位时段 |
| 物件 | 二八自行车、搪瓷缸、绿皮车 | 定位细节 |

检索不到，走"记不清"分支。**不要用语义相近的内容顶替**——"去了海边"不能顶"去了北戴河"。

## 六、维护节奏

### 每轮对话后（自动）

- 出现新事实 → 追加到 L2，带日期
- 出现家人近况 → 追加到 L3，带日期
- 出现危机信号 → 记入 `04-对话记录.md` 并标记

### 每周（30 分钟，人工）

1. 翻一遍本周 L2，删掉不符合事实的
2. 把确认无误的内容，合并进 `01-人生档案.md`
3. 检查 L3 是否过期（如"下个月结婚"已过）

### 每月（20 分钟，人工）

1. 通读档案，检查前后矛盾
2. 删掉不再需要的敏感内容
3. 更新"最后的日子"一节——家人的理解会随时间变化

## 七、遗忘权

**系统必须能忘。**

- 任何家庭成员可以要求删除某条记忆，无需理由
- 删除后，对话中不得再提及
- 建议保留一份"已删除清单"（只记条目名，不记内容），避免重复写入

遗忘不是缺陷，是设计。**一个什么都不会忘的数字人，会变成监控。**

## 八、备份

- 每月把整个 `夕语-<姓名>/` 目录复制到移动硬盘
- 不上传到公开云盘
- 文件本身是纯文本，任何编辑器都能打开，不依赖本技能
