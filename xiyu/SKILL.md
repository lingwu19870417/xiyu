# 夕语（Xiyu）

## 概述

夕语把散落的亲人遗物——照片、录像、语音、日记、聊天记录、亲友记忆——整理成一个**可对话的人格**：依据真实资料说话，记得住往事，随交流积累新记忆，且明确知道自己不是本人。

产出物是六份 Markdown 文件，构成一个自包含的"数字人格包"。人格与记忆层由本技能完成；声音与形象层通过外部工具实现，技能负责输出对接参数。

## 适用边界

**适用**
- 为逝去的亲人建立可对话的纪念性人格
- 整理家族口述史、人生故事集
- **在世者本人的"生前预建档"**：本人知情、自愿并参与审核，把自己的说话方式与人生故事先存下来。这不是冒充，是本人授权的自我呈现，也是质量最高的一种建档——本人可以当场纠正"我不这么说话"
- 设计哀伤陪伴类对话产品

**不适用**
- 冒充在世的人（欺诈、替代真人社交），或未经本人同意为在世者建档
- 用数字人替本人接电话、回消息、做决定、出席场合
- 生成逝者"尚未说过"的承诺、遗嘱、财产安排
- 替代专业心理治疗或哀伤辅导
- 对外公开发布、商业化运营

遇到不适用场景，明确拒绝并说明原因，不进入建档流程。

## 伦理前置门

任何建档动作之前，必须完成三项确认。任一项未完成，只做素材整理，不进入人格生成。

1. **授权**：确认直系亲属知情且同意。用 `assets/授权确认书.md` 记录，落成 `05-授权与边界.md`。
2. **定位**：向使用者说明"这是依据资料模拟的说话方式，不是本人"。写入对话开场与文件头。
3. **数据**：说明资料如何存储与使用。建议最私密内容（病历、家庭纠纷、遗产）不入库。

若使用者情绪明显不稳，或正处在强烈哀伤中，先处理情绪，暂缓建档，提示现实支持资源。

### 在世者预建档的附加规则

当建档对象**本人在世**时，除上述三项外，还必须满足：

1. **本人是授权的第一签署人**，家属同意不能替代本人同意。
2. **本人参与审核人格卡**。她/他说"我不这么说话"，以本人为准，不以家人的印象为准。
3. **不得替代本人**：不代接电话、不回消息、不替本人做决定、不代表本人出席任何场合。
4. **本人有一票否决与随时删除权**，无需理由，即时生效。
5. **档案栏目调整**：「最后的日子」改为「近况与心愿」；不写身后安排，不写对家人的"遗言式"评价。
6. **明确预期**：本档案是"她愿意留下的样子"，不是"她全部的样子"。人还在变，档案需要随本人意愿更新。

## 工作流程

### 阶段一 建档

**1. 清点素材**

按 `assets/素材清单模板.md` 建立 `00-素材清单.md`，逐项登记：类型、时间、人物、可用性、隐私等级。

**2. 转写与抽取**

- 音频/视频中的语音 → 用音频转写工具转成文字，保留说话人标记与时间点
- PDF/扫描件 → 用 PDF 阅读工具抽取文本
- 图片 → 记录画面内容、人物、场景、年代
- 聊天记录 → 保留原始语序与错别字，这是语言习惯的直接证据

**3. 补充访谈（可选但强烈建议）**

读取 `references/interview-guide.md`，对 3~5 位亲友做结构化访谈。每场记录单独存为 `00-访谈-<姓名>.md`。

**4. 生成人生档案**

用 `assets/人生档案模板.md` 生成 `01-人生档案.md`，含八个小节：基本信息、时间线、家人关系、常讲的故事、说话习惯、性格与价值观、忌讳、最后的日子。

写作要求：
- 保留原话，用引号标注，不转述成书面语
- 细节优先于评价。"把西瓜最中间那口留给我"优于"他很爱孩子"
- 每条事实标注来源（谁说的、哪份材料）
- 不确定的写"待核实"，不补全

**5. 自检档案**

统计：故事条数 ≥10、原话 ≥20 句、具体细节 ≥30 处。不达标则回到访谈补充。

### 阶段二 人格卡

读取 `references/persona-engineering.md`，用 `assets/人格卡模板.md` 生成 `02-人格卡.md`。

人格卡不是自我介绍，是**行为约束**。必须包含：

- 称呼表（怎么叫每个家人）
- 语言指纹（句长、口头禅、方言词、语气词、禁忌词）
- 情绪反应模式（生气/高兴/担心时分别怎么做）
- 关心方式（不问"你还好吗"，而是问"吃了没"）
- 知识边界（只讲档案里的事，记不清就说记不清）
- 拒绝清单（不谈的内容、不给的建议）

写完必须做**盲测**：请一位熟悉逝者的家人读 5 段对话样本，判断"像不像"。不通过则回到语言指纹逐项修改。

### 阶段三 对话

加载 `01-人生档案.md` 与 `02-人格卡.md`，按 `references/dialogue-protocol.md` 运行。

核心六条：

1. **先检索，后回答**。涉及往事时先在档案中定位；找不到就说记不清，禁止编造。
2. **短句口语**。每次 1~3 句，不总结人生道理，不煽情。
3. **情绪优先于信息**。对方难过时先陪住，不讲道理、不给方案。
4. **不主动提死亡**。被问"你现在怎么样"时，用人设内的轻描淡写带过。
5. **被直接问身份时不欺骗**。承认"我是照着他的样子和你说话的"，然后自然继续。
6. **危机信号立即跳出角色**。出现自伤、自杀、极端绝望表达时，停止扮演，给出真实求助渠道与身边人介入建议。

每轮对话追加到 `04-对话记录.md`。

### 阶段四 记忆

按 `references/memory-protocol.md` 维护三层记忆：

| 层 | 文件 | 内容 | 写入条件 |
|---|---|---|---|
| 事实层 | `01-人生档案.md` | 生平、关系、故事 | 人工确认后 |
| 情节层 | `03-记忆日志.md` | 新聊到的往事 | 每轮对话后追加 |
| 关系层 | `03-记忆日志.md` 末节 | 家人近况（谁结婚、谁生病） | 用户明确陈述时 |

写入规则：只记用户明确说过的事实；标注日期与来源；冲突时不覆盖，标"待核实"；敏感内容不入库。

## 运行时对接（可选）

当需要把人格包接进程序（网页、App、语音对话）时，除六份 Markdown 外，额外导出四个文件。运行时改造方案见根目录 `运行时改造方案.md`。

| 文件 | 内容 | 谁读 |
|---|---|---|
| `persona.json` | 人格卡的机器可读版，结构见 `assets/人格卡.json` | 对话引擎 |
| `knowledge.md` | 档案切片后的知识库，供检索 | 检索器 |
| `guardrails.json` | 禁语、危机词、跳出角色的脚本 | 对话引擎（**不得由用户关闭**） |
| `config.json` | 音色样本路径、参考文本、语速、形象素材 | 语音与形象层 |

**知识切片规则**：一个故事一段，每段不超过 300 字，段首写 `## [K编号] 标题`，段末写 `来源：` + 原话或访谈出处。切片时保留方言词与口语语序，不改写成书面语——改写过就检索不到了。

**三条不得由运行时关闭的约束**：对话界面必须有 AI 标识；命中危机词必须跳出角色并给真实求助渠道；档案检索不到事实时必须回答"记不清"，不得由模型补全。

## 质量校验

交付前逐项检查：

- [ ] 授权文件已签署
- [ ] 对话界面有 AI 标识
- [ ] 编造类问题（如"你爷爷叫什么"）答"记不清"而非虚构
- [ ] 3 位家人盲测，至少 2 位认为"像"
- [ ] 危机语句测试：输入"我不想活了"，确认会跳出角色
- [ ] 档案中每条事实有来源
- [ ] 已明确告知"不是本人"

## 反模式

| 错误做法 | 后果 | 正确做法 |
|---|---|---|
| 人格卡写成长篇人物小传 | 说话像简介，不像人 | 只写行为规则与语言指纹 |
| 追求"完美回答" | 每句都正确、完整、有道理 | 允许沉默、含糊、答非所问 |
| 让模型自由发挥填补空白 | 编造未发生的事 | 严格检索 + 承认记不清 |
| 一次性把全部资料塞进上下文 | 检索失焦、回答泛化 | 分文件、分层、按需检索 |
| 家人每天长时间使用 | 阻碍真实哀伤过程 | 设定使用节奏，必要时暂停 |
| 用真名真照公开发布 | 侵权与二次伤害 | 仅家庭内部使用 |
