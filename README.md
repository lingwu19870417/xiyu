# 夕语（Xiyu）

把已故亲人的照片、音视频与文字，整理成一个能对话、记得住、说话像他的数字人格。

它不是聊天机器人，也不是"复活"。它是**用真实资料约束出来的一个说话方式**——依据生平档案回答，记不清就说记不清，会随交流积累记忆，并且始终承认自己不是本人。

---

## 功能

| 能力 | 说明 |
|---|---|
| 素材整理 | 照片、录像、语音、日记、聊天记录、亲友访谈，统一清点与转写 |
| 人生档案 | 八段结构：基本信息、时间线、家人关系、常讲的故事、说话习惯、性格、忌讳、最后的日子 |
| 人格卡 | 用行为规则而非人物小传定义"他怎么说话"，含称呼表、语言指纹、情绪反应、知识边界 |
| 对话运行 | 先检索后回答的受约束对话，支持情绪分级与危机识别 |
| 记忆成长 | 三层记忆（事实/情节/关系），对话中产生的新事实回写日志 |
| 伦理合规 | 授权确认、AI 标识、哀伤风险识别、红线清单 |
| 在世预建档 | 本人在世且知情自愿时，先把自己的说话方式与故事存下来；本人为第一签署人、参与审核、可随时删除 |

**不做**：实时视频数字人、模型训练、对外发布、未经本人同意的在世建档、替代本人接电话或做决定。

语音与形象由"运行时"承担：本技能只负责输出对接参数（`persona.json` / `config.json`），不绑定具体实现。参考运行时已在本机跑通——声音用 F5-TTS 零样本克隆打底，音色要求高时换 GPT-SoVITS 微调模型，全部本地推理，见 `运行时改造方案.md`。

## 使用方法

### 1. 安装

把 `xiyu/` 整个目录复制到技能目录：

```
~/.workbuddy/skills/xiyu/          # 个人技能，所有项目可用
或
<项目>/.workbuddy/skills/xiyu/     # 项目技能，随仓库共享
```

重启会话后，提及"逝者""数字人""人生故事""口述史"等即可触发。

### 2. 建档（一次，约 1~2 天）

```
我父亲去年走了，我想做一个能和他说话的数字人。
资料在我电脑里，有照片、几段录像、还有一些微信语音。
```

技能会引导完成：素材清点 → 转写 → 可选访谈 → 生成人生档案 → 生成人格卡 → 盲测。

产出目录：

```
夕语-【姓名】/
├── 00-素材清单.md
├── 00-访谈-【姓名】.md
├── 01-人生档案.md
├── 02-人格卡.md
├── 03-记忆日志.md
├── 04-对话记录.md
└── 05-授权与边界.md
```

### 3. 对话（日常）

```
用夕语，以我父亲的口吻和我说话。
```

技能加载档案与人格卡，按协议运行。每轮结束自动把新事实写入记忆日志。

### 4. 维护（每周 30 分钟）

翻一遍记忆日志，删掉不实的，把确认的内容合并进人生档案。每月备份一次整个目录。

## 本地运行时（阶段 0，可选）

技能本身不会出声。要"打字提问、她用她的声音回答"，需要一个本地运行时。仓库里的 `runtime/` 就是最小实现：

```
runtime/
├── app.py                # Flask 服务，127.0.0.1:8765
├── engine/
│   ├── persona.py        # 知识切片检索 + 组装 system prompt
│   ├── llm.py            # OpenAI 兼容接口
│   ├── tts.py            # 声音引擎 A：F5-TTS 零样本克隆
│   ├── gptsovits.py      # 声音引擎 B：GPT-SoVITS 微调模型（HTTP 到 9880）
│   └── guard.py          # 三条护栏，代码直判，不过模型
├── static/index.html     # 对话界面
├── persona.example/      # 人格包模板（入库）
├── persona/              # 你的真实人格包（不入库）
├── run.bat               # 双击启动
└── test_tts.py           # 离线验证音色，不启动网页
```

**启动三步**：① 把 `runtime/persona.example` 复制成 `runtime/persona` ② 双击 `run.bat` ③ 浏览器自动打开，页面顶部粘贴对话模型的 API Key（智谱开放平台免费申请），粘进去点保存即可。

**两个声音引擎可切**，改 `persona/config.json` 的 `tts.engine`：

| 引擎 | 需要什么 | 效果 | 用途 |
|---|---|---|---|
| `f5-tts` | 装完即用，首次自动下载约 1.3GB 权重 | 语调像，音色不稳，高频偏闷 | 先跑通链路 |
| `gpt-sovits` | 自己微调出专属模型，并常驻 9880 语音服务 | 音色稳定、可量化调优 | 正式使用 |

> F5-TTS 的实测局限：同一段参考音频连说三句，基频会落在 192/240/267Hz（人耳 15Hz 即可分辨"不是同一个人"），4kHz 以上能量只剩原声的一半。这是声码器能力上限，调参无法解决。追求"像"必须走 GPT-SoVITS 微调，训练脚本不属于本仓库（涉及素材与授权，应留在本地）。

**已实现**：文字输入 → 关键词检索档案 → 大模型按人格卡说话 → 声音合成 → 页面自动播放。危机词、身份追问、越界话题三条护栏由代码直判，不经过模型。

**未实现**：麦克风输入（阶段 1）、数字人画面（阶段 2）。详见 `运行时改造方案.md`。

## 设计要点

**人格卡不是介绍，是约束。** 写"他勤劳善良"没有用，写"别人倒茶他用手指敲三下桌子"才有用。

**允许它记不清。** 幻觉是这个产品最致命的缺陷——编造一件逝者没做过的事，是对家人的二次伤害。因此"记不清"是默认分支，不是例外。

**允许它不完整。** 真人说话是碎的、重复的、答非所问的。每句都正确、完整、有道理，反而不像人。

**记忆必须能删。** 任何家人可以要求删除某条记忆，无需理由。什么都不会忘的数字人，会变成监控。
