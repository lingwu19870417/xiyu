# 读稿录音（数据采集包）

这是"夕语"声音克隆的数据采集与训练流水线。**核心区别：标注不用机器猜，用稿子。**

## 为什么换成读稿

| | 采访素材（上次） | 读稿录音（这次） |
|---|---|---|
| 素材 | 36 分钟双人采访 | 12 分钟单人读稿 |
| 标注 | ASR 猜的，方言错误率极高 | **稿子原文，零错误** |
| 机器的作用 | 既要听懂又要写字 | 只需判断"这是第几句" |
| 结果 | 声音不可懂，声纹 0.774 | 103/103 全对齐、零补读；但**纯读稿版声纹反而低于基线**（朗读腔离日常腔远），混合训练才追平 |

## 三步走

```
1. 打印 读稿卡.html → 她按 操作单 录 4 个文件 → 丢进 raw\
2. 双击 一键整理.bat   → 看 out\报告.md（已采用 / 需补读）
   需补读的句子单独补录 → 放进 raw\补录\ → 再跑一次（补录用命令行 --merge-to）
3. 双击 一键训练.bat   → 权重落在 SoVITS_weights_v2Pro\xiyu_rd_e*.pth
```

补录合并的命令：

```bat
runtime\python.exe 读稿录音\tools\align_script.py ^
  --audio 读稿录音\raw\补录 --script 读稿录音\out\需补读.txt ^
  --out 读稿录音\out_补录 --merge-to 读稿录音\out\list.txt
```

## 判定标准

- **已采用 ≥ 140 句（约 10 分钟）** → 直接训练
- 已采用 100~140 句 → 也能训，但补到 140 更稳
- 低置信条目 → 抽听 3~5 条，确认不是"张冠李戴"
- 需补读里出现"太短 / 静音多 / 音量低" → 那是录音环境或她中途停顿的问题，补录时注意

## 对齐是怎么做的（给未来的自己看）

1. 按静音切片（-38dB / 最短 1.5s / 段间留 450ms），记录每段在原始 wav 的采样点跨度
2. Whisper-large-v3 逐段识别，`initial_prompt` 喂稿子前 8 句 → 识别结果贴近稿子用词
3. **单调全局对齐**（Needleman-Wunsch）：音频段序 ↔ 稿子句序，允许
   - 一句吃 1~3 个碎片（她句子中间有停顿会导致过切）
   - 跳过音频段（重读、口误、咳嗽）
   - 跳过稿子行（漏读）
   匹配分数 = 0.8×文本相似度 + 0.2×时长合理度；合并时长不得超过该句应有长度的 1.8 倍（防止把上一句的重读吞进来）
4. **标注一律取稿子原文**，ASR 文字只用于打分
5. 从原始 wav 截取首段起点 → 末段终点的完整跨度，两端按 -42dB 修边（头 50ms、尾 150ms）
6. 质检：时长、RMS、静音占比、爆音；"文字对不上但前后句严丝合缝"→ 判为低置信采用（方言场景常见），不浪费素材

## 已踩过的坑

- `runtime/python39._pth` 必须包含 `..`、`../GPT_SoVITS`、`../tools`，否则导入失败
- `s2_train.py` 只要 `logs/<exp>/logs_s2_v2Pro/G_233333333333.pth` 存在就会 resume 到旧轮次（哪怕改小 epochs 也直接"训练完成"）→ 脚本已自动改名为 `_bak_时间戳`
- 预处理产物带 `-0` 后缀，训练要的是 `2-name2text.txt`、`6-name2semantic.tsv` → 脚本已自动复制改名
- v2Pro 额外需要 `7-sv_cn`（说话人向量），WebUI 里没暴露，用 `prepare_datasets/2-get-sv.py`
- v2 系官方建议 **8 轮**；15 轮在 24 段样本上明显过拟合（音高飘 +11Hz）
